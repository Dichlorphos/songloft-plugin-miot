# 切换设备播放上下文同步

- 状态：提议
- 日期：2026-09-12

## 决策

按账号保存一条本插件最新成功播放快照。切换到未加入设备组的独立目标设备后，异步保存未过期快照为目标设备的待播放上下文，不覆盖目标 PlaylistManager，也不向音箱自动播放；用户复用现有播放/继续按钮或语音 resume 后才起播。

快照只覆盖正式歌单歌曲，包含歌曲、歌单、索引、位置、倍速、播放模式、状态和来源设备。播放至少一台目标设备成功后写入，pause 写入 paused 位置，stop 保留 stopped 状态。playing 使用写入时采样的位置，不做后台外推。

## 取舍

复用现有设备选择、PlaylistManager、URL、seek、倍速和 GroupCoordinator 边界，不新增面向用户的最近播放入口，也不新增切换 API。设备组完全沿用原有实现。

## 失败处理

无有效快照、歌单加载失败或目标设备离线时保留目标原上下文；切换接口维持现有成功语义，失败记录日志并由后续播放动作报告。歌曲按 ID、索引、歌单首曲回退，歌单不存在则保持目标现状并返回错误。快照存储失败不影响核心播放控制。

## 语音控制

普通语音和 AI 均区分 pause、stop、resume。pause 调用已有 PlaylistManager.pause()，保留位置并更新快照；stop 调用 PlaylistManager.stop()；resume 只使用目标 PlaylistManager 当前上下文。旧 AI 返回 stop 时保持停止兼容语义。

## 实现约束

切换场景不得复用会发送 URL 或触发 resumeAfterReload 的初始化路径。必须区分插件启动/热重载恢复与用户设备切换：前者保持既有自动恢复，后者只执行内存上下文加载。上下文加载和真正起播使用不同的内部操作，确保切换不会产生声音或自动切歌。

## 活动播放设备决策

为避免本地 PlaylistManager 与音箱实际内容不一致，目标设备正在播放时不立即覆盖活动上下文，而是保存待播放上下文。相同上下文重复切换不重复加载。现有播放/继续动作负责消费待播放上下文并完成一次性覆盖和起播；成功后清除待播放上下文。目标停止或暂停时可提前加载，但不发播放命令。
