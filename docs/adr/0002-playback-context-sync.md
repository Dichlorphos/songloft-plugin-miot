# ADR-0002：切换设备使用待播放上下文

- 状态：已采纳
- 日期：2026-09-12（提议）、2026-09-19（采纳）

选择将待播放上下文与目标活动上下文分离，避免仅切换设备就打断播放或使本地状态与音箱不一致。设备组沿用共享 PlaylistManager，避免引入第二套组内协调机制。

代价是需要管理一份独立上下文及其生命周期，设备间也不会自动保持实时播放位置一致。快照使用账号内单调 revision 并把位置可用性显式建模，避免以墙上时钟或数值 0 猜测并发和采样结果；电台通过内容类型区分来源、身份沿用 song_id，因为宿主与 SDK 都不提供独立的电台标识，凭空造一个字段只会得到一个无法解析的契约。同步状态分别存放在版本化的专用存储键中，便于拒绝试做数据并保持数据结构可校验。设备组不作为跨设备快照来源，避免跨账号组成员无法归属；待播放上下文保存完整副本，避免源快照变化影响已排队目标；结果不确定时保留两侧本地记录，避免重复下发造成串播。快照与待播放上下文是两类不同的东西——前者是按账号的观测结果，后者是按账号与目标设备的决策产物——因此分属两个独立存储键与模块，而不是一个信封里的两张表。快照只在播放状态机的出口记录，而不是在每个调用入口埋点：入口会随功能增加而漂移，出口不会，且出口天然覆盖网页、语音、定时任务与内部自动停止。完整行为和验收以[完整需求规范](../../.scratch/playback-sync/spec.md)为准；代码基线及还原历史见其[代码基线](../../.scratch/playback-sync/spec.md#代码基线)。
