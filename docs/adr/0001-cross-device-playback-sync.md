# ADR-0001：跨设备播放同步采用插件内协调服务

- 状态：提议
- 日期：2026-09-12

## 背景

插件部署在 FNOS Docker 中，播放状态和 URL 生成由插件内部管理。外部脚本无法可靠复用 PlaylistManager 的 seek 偏移、倍速、设备缓存和持久化语义。

## 决策

在插件内增加 PlaybackResumeService。它读取 resolvePlayerStatus 的融合状态，按账号持久化一份最近播放快照。切换音响时只更新当前设备和进度视图，不自动下发播放；用户明确点击播放或继续播放后，才执行一次带 seek 的恢复。取消后台实时镜像和持续轮询同步。

一期提供“切换音响”和“播放最近进度”两个独立动作。切换本身不打断目标设备，也不自动产生声音。

## 取舍

插件内实现可复用现有认证、状态缓存和 URL 构建，减少部署组件；一次性续播的实现和故障边界更清晰，也不会因高频控制造成云端限流或重复起播。代价是不同音响之间不会自动保持实时进度一致。最近快照有效期为 30 分钟，失效后回退到每设备/每歌单进度。

## 失败处理

unknown、超时或离线只记录日志并保留最近快照；目标推送失败直接返回错误，不连续重推；目标已有播放时默认不打断；Docker 重启后不自动起播。
