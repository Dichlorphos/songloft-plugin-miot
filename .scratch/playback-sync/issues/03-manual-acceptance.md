## 目的

自动化验证已经覆盖纯逻辑、宿主集成、前端合同与构建，但无法代替真实 MIoT 设备、真实网络、真实存储和真实播放服务。本票据把 spec 的「真机验收」拆成可执行清单；`Status: done` 只表示实现与自动化验证完成，不代表本票据通过。

自动化验证现状（2026-09-21）：`npm test` **181 项**通过、`npm run typecheck`、`node frontend/tests/run.mjs`、`npm run build` 通过。本次新增 `src/player/reload_restore_guard.test.ts`（12 项）锁定重启恢复的硬条件判据与清洁停机标记。本次补齐了此前零覆盖的 I1–I6、D4（unknown 真实链路）、H1/H3（Music API 开关判定）、快照出口接线断言；G4 的 pause/stop 分离已按规格实现。真机结果必须以实际观察和证据为准，不得用自动化结果代替。

## 验收边界

- 验收环境：同一测试账号下至少两台独立 MIoT 设备、一个包含至少两台成员设备的设备组、一台可模拟离线/未启用管理的设备。
- 播放源：正式歌单、电台、特殊歌曲（缺歌、空歌单、未知时长、接近曲尾）各至少覆盖一次。
- 网络降级：至少覆盖一次超时或 unknown；如条件允许，补一次弱网或断网。
- 安全：优先使用可回滚的测试账号和测试歌单；若必须使用真实账号，先导出备份账户、歌单进度和相关存储。
- 证据：每项记录结论（通过/失败/阻塞）、时间、设备、当时的插件构建 hash 和日志片段。失败不得标记通过；应新建 bug 票据并保留本票据为阻塞状态。

## 检查清单

### A. 独立设备与恢复

- [ ] A1 独立设备 A 正在播放正式歌单，切换到独立设备 B：B 不收到播放/暂停/停止命令，不自动起播；切换完成后 B 有待播放上下文。
- [ ] A2 在 B 明确继续：恢复原歌单与原歌曲；命中原 song_id 时位置来自切换请求开始时的固定采样，误差相对采样时刻不超过 5 秒。
- [ ] A3 源设备处于暂停态：保存暂停位置；在目标继续后从该位置恢复。
- [ ] A4 源设备处于 stopped：保存停止前位置；stopped 不自动起播，用户明确继续后**从停止位置继续**（不是从头重播）；位置不可用（0）时才从头播。
- [ ] A5 源设备与目标设备相同、无旧设备或跨账号切换：不创建错误的待播放上下文，不把源账号快照写入目标账号。

### B. 设备组

- [ ] B1 独立设备 → 设备组成员：完全跳过同步，不写待播放上下文，组内播放不被切换动作打断。
- [ ] B2 设备组成员 → 独立设备：同样完全跳过同步。
- [ ] B3 设备组共享播放管理器仍正常；组内设备不产生跨设备快照同步。

### C. 快速连续切换与并发

- [ ] C1 快速 A → B → C：最终当前选择为 C，旧任务不得覆盖新目标；每个目标的待播放上下文与各自源设备相符。
- [ ] C2 同一目标连续选择（源设备不同）：后发选择胜出；先发任务的晚到待播放上下文不得覆盖后发任务。
- [ ] C3 继续操作与切换同步并发：继续先等待同一目标的未完成同步，再消费待播放上下文。
- [ ] C4 切换同步未完成时选择新歌单或新歌曲：pending 在加载与起播前被清除；旧同步任务不得把旧上下文重新写回。
- [ ] C5 前端快速点选设备：响应返回后读取目标设备状态，不出现旧设备状态闪烁或错配。

### D. 网络与设备异常

- [ ] D1 源设备离线、unknown 或采样超过 2 秒：保留旧快照；目标可使用未过期的固定位置；目标原上下文不因采样失败被清空。
- [ ] D2 目标设备离线、unknown 或未启用管理：仍可保存 pending；只有用户继续时才报告失败，失败后 pending 保留且不自动重播。
- [ ] D3 加载歌单、生成 URL 或下发前失败：目标不变，pending 保留。
- [ ] D4 下发后超时或结果 unknown：对外报告 `success:false` 与 `outcome:'unknown'`，不回滚设备、不清 pending、不自动重播旧歌曲。

### E. 内容变化与特殊歌曲

- [ ] E1 切换后源歌单/歌曲发生变化：继续时按 song_id 命中则恢复位置；回退到其它歌曲时从 0 秒开始。
- [ ] E2 歌单不存在或为空：返回错误并保留目标原上下文与 pending。
- [ ] E3 电台：按 song_id 恢复同一播放服务歌曲，位置固定 0；取不到时保留 pending 并报告失败。
- [ ] E4 未知时长、接近曲尾或 seek 精度不足：按降级行为验收，不套用精确位置要求；不得崩溃或误判自动切歌。
- [ ] E5 临时歌单、外部 URL、单曲直推和外部播放不参与快照；外部搜索结果导入正式歌单后参与。
- [ ] E6 自动切歌成功更新账号级快照；自动切歌失败保留上一条有效快照。

### F. 重启、过期与生命周期

- [ ] F1 切换写入 pending 后重启插件（30 分钟内）：当前选择和 pending 均可恢复，继续可正常使用。
- [ ] F2 pending 超过 30 分钟：按不存在处理，目标保留原上下文；有效期从首次写入起算，去重不刷新。
- [ ] F3 快照超过 30 分钟：源设备仍在播放且本次采样成功时可创建新 revision；采样失败保留旧记录。
- [ ] F4 删除账号：快照和 pending 同时清除；新建或复用同标识账号不继承旧数据。

### G. 语音、AI 与旧行为

- [ ] G1 目标正在播放时调用 toggle：执行暂停，不消费 pending。
- [ ] G2 目标未播放且有有效 pending 时 toggle：优先消费 pending。
- [ ] G3 明确 resume：优先消费 pending；没有 pending 才使用目标原活动上下文。
- [ ] G4 旧 AI 返回 `stop`：始终按停止处理；只有明确解析为 `pause` 才暂停。
- [ ] G5 插件启动和热重载：设备确实还在放我们的流时接管定时器；设备没在放/在放别的媒体/流长对不上/状态查不到时钉死 `stopped` 并保留停止位置，**绝不被重推 URL 叫醒**；`paused` / `stopped` 锚点只还原本地状态、不下发指令。切换路径不得触发 `resumeAfterReload` 的自动起播。
- [ ] G6 防隔夜叫醒（硬条件）：插件停止一夜后重新启动，再打开网页触发惰性建 manager；音箱不得被重新推流叫醒。含两种情形——① 设备早已停播；② 设备因断电/崩溃被异常终止（无清洁停机标记）后即使仍在放流也不接管。
- [ ] G7 停止位置活过重启：停止播放后重启插件，用户明确继续时仍从停止位置带 `seek` 重推，而不是从头重播。

### H. Music API 播放方式开关（X08E 等触屏型号）

- [ ] H1 默认清单内型号（如 X08E）在设备设置里可取消勾选；取消后播放走 `player_play_url`，不再触发「播放服务遇到问题」播报。
- [ ] H2 重新勾选后恢复 `player_play_music` 路径，触屏歌词/曲库联动仍可用。
- [ ] H3 不在默认清单内的型号：勾选框置灰，播放始终走直链，不受本开关影响。
- [ ] H4 设置页列出的型号与实际账号下设备一致；未接入设备的默认型号以提示列出，不产生误导。
- [ ] H5 开启「调试日志」时，推流日志包含脱敏后的 URL（`access_token=<redacted>`），不含明文 token；关闭时不打印。
- [ ] H6 Music API 下发成功后 2 秒回读播放状态；若设备未拉流，日志能体现该静默失败。

### I. 不可播放歌曲自动跳过（#466）

- [ ] I1 正式歌单中夹一首音源解析失败的歌：该首在 10+8 秒探测窗口内未起播时，自动跳到下一首并播 TTS「这首歌暂时无法播放，为您切换下一首」。
- [ ] I2 电台或 singlePlay 模式遇不可播放：不跳歌，播 TTS「当前歌曲暂时无法播放，请稍后再试」并停播，不出现异常循环。
- [ ] I3 连续 3 首起播失败：触发熔断，播 TTS「当前多首歌曲无法播放，请稍后再试」并停播，不把整个歌单跳完。
- [ ] I4 预取失败标记的歌在切歌时被直接跳过，不占用 10+8 秒起播确认窗口；切歌听感无明显多余停顿。
- [ ] I5 外部停止发生在起播早期（position < 15 秒）：按起播失败处理（可跳歌则跳、电台/单曲则停），不停留在假 playing 状态。
- [ ] I6 正常歌曲起播不受影响：起播确认成功时熔断计数清零，不误报 TTS、不误跳下一首。
