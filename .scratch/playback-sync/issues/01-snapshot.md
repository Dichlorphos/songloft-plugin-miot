# 建立账号级最新播放快照

Type: task
Status: ready-for-agent

任务目标：建立账号级最新播放快照的采集、持久化与生命周期管理，并对外提供切换时的位置采样入口，供任务 02 使用。

需求与验收入口：[实现边界](../spec.md#实现边界)、[快照范围与生命周期](../spec.md#快照范围与生命周期)、[数据契约](../spec.md#数据契约)、[验收](../spec.md#验收)中的快照相关场景。代码基线见[完整需求规范](../spec.md#代码基线)。

## 交付边界

- 快照只在 `PlaylistManager` 状态机出口记录（起播成功、暂停完成、停止完成、自动切歌成功或失败、单曲结束），不在各调用入口埋点。出口处显式判定范围：正式歌单且独立设备才记录，临时歌单与设备组跳过。
- 播放快照存储（按账号）与待播放上下文存储（按账号与目标设备）是两个独立模块与独立存储键，本任务只交付前者；待播放上下文由任务 02 交付。
- 本任务必须对外暴露切换时的位置采样入口：给定源设备，采样物理位置并按 revision 规则写入快照；采样失败保留旧快照且不产生新 revision。任务 02 在设备选择入口调用它，本任务不接线。
- 电台身份沿用 `song_id`，以 `content_type=radio` 与 `playlist_id=null` 区分来源；当前宿主与 SDK 不提供独立电台标识，不引入 `radio_id`。

- 2026-09-13：同一账号与目标设备只保留最新待播放上下文；账号删除时清理快照、待播放上下文和 revision 计数。
- 2026-09-13：已确认 `source_device` 使用 `{ account_id, device_id }`；正式歌单使用 `content_type=playlist` 与 `playlist_id`。
- 2026-09-13：已确认待播放上下文保存完整不可变副本；设备组播放不更新跨设备快照；所有插件主动状态变更统一采集，暂停升级停止时按 `stopped` 保存。
- 2026-09-13：已确认自动切歌成功更新快照，失败保留上一条；坏数据按单条忽略，位置采样超时阈值为 2 秒。

- 2026-09-19（框架复盘，已采纳）：快照记录点定在播放状态机出口而非调用入口清单，出口处显式判定范围。原方案要求「所有主动改变状态的路径都更新快照」，但代码里并不存在统一收口：`setPlayMode`、`setPlaybackSpeed`、seek 不走 `persistState`，`next`/`previous`/自动切歌直接改 `currentIndex`，入口清单会随功能增加持续漂移。
- 2026-09-19（框架复盘，已采纳）：播放快照与待播放上下文拆成两个模块、两个存储键（`playback_snapshot_v1`、`playback_pending_v1`），取代原 `playback_sync_v1` 单信封。两者键空间与生命周期不同：前者按账号、后者按账号与目标设备。
- 2026-09-19（框架复盘，已采纳）：电台身份改用 `song_id`，撤销 `radio_id` 契约。全仓库与 SDK 类型中都不存在 `radio_id`，`Song` 只有 `id`/`type`/`is_live`，原契约没有对应接口。
- 2026-09-19（框架复盘，已采纳）：本任务需暴露切换时的位置采样入口；采样入口的调用方在任务 02。
