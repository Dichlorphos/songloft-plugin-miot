# 音响切换同步需求

Status: ready-for-agent

## 代码基线

当前处于需求整理阶段；试做已还原，本需求相对于试做前没有业务代码改动。`11bd80b` 是试做前基线；`94ce724`、`8b01630` 是历史试做；`ab3a53f` 还原试做。当前 HEAD 与试做前基线的差异仅限需求 Markdown 文档。

当前源码不存在播放快照、待播放上下文、快照记录出口或最近播放接口。既有播放管理器、设备控制、设备级进度和热重载恢复属于原有能力。

## 目标

切换到未加入设备组的独立目标设备时，异步保存账号级最新播放快照为该设备的待播放上下文。复用现有播放、继续和设备选择入口及现有播放管理器；设备组继续使用共享 `PlaylistManager`。不新增最近播放入口或切换 API。

## 实现边界

- **快照记录点是播放状态机出口，不是入口清单。** 快照只在 `PlaylistManager` 的状态出口记录：起播成功、暂停完成、停止完成、自动切歌成功或失败、单曲结束。网页、普通语音、AI、定时任务、睡眠定时器和内部自动停止都经同一组出口，因此不按入口逐个埋点，也不存在新增入口漏记的漂移。
- **出口处显式判定范围。** 只有正式歌单（`playlist_id > 0`）且该管理器代表独立设备（单一输出目标）时才记录；临时歌单与设备组在出口处直接跳过，不依赖调用方自觉。
- **观测与决策产物分属两个模块。** 播放快照存储按账号保存观测结果；待播放上下文存储按账号与目标设备保存决策产物。两者的键空间、生命周期和失效规则不同，各自独立读写；切换路径只写待播放上下文，不写快照。
- **切换时的位置采样是快照模块的一次刷新。** 切换入口只提供源设备与目标设备，采样与写盘由快照模块完成；采样失败保留旧快照，不影响切换本身返回成功。
- **电台身份沿用歌曲身份。** 当前宿主与 SDK 均不提供独立的电台标识，电台快照与正式歌单歌曲一样以 `song_id` 作为身份依据，另以 `content_type` 区分来源；若宿主后续提供稳定的不透明电台标识，再以新 `schema_version` 引入。

## 快照范围与生命周期

- 快照只来自本插件成功播放的正式歌单歌曲；电台是纳入范围的明确例外，位置固定为 0；临时歌单、外部 URL、单曲直推和外部播放不参与。外部搜索结果导入正式歌单后按正式歌单歌曲处理。
- 符合范围的播放至少一台目标设备成功后写入快照；快照存储失败不影响核心播放控制。
- 快照按账号保存一条；不同独立目标设备分别保留待播放上下文，严格按 `account_id` 隔离。
- 同一 `account_id + target_device_id` 只保留最新待播放上下文；新 revision 覆盖旧上下文，旧异步任务不得回写。
- 待播放上下文保存快照的完整不可变副本，并附带 `source_revision`、`target_device_id`、`created_at` 和 `expires_at`；后续源快照变化不改写已保存的目标内容。
- 源设备固定为切换请求开始前当前选中的设备；没有旧设备、源设备与目标设备相同，或跨账号切换时不创建同步任务。
- 快照包含账号、`content_type`、`song_id`、`playlist_id`、索引、位置、`position_available`、倍速、播放模式、状态、`source_device`、更新时间、账号内单调递增的整数 `revision`、诊断标题/歌手和整数 `schema_version`。`source_device` 结构固定为 `{ account_id, device_id }`，不保存设备名称。
- `playing` 在切换请求开始时采样源设备物理位置；采样失败保留旧快照。恢复使用固定采样位置，不额外外推，误差相对采样时刻不超过 5 秒。
- pause 保存暂停位置；stop 保存停止前位置并标记 `stopped`。stopped 不自动起播，用户明确继续后仍可恢复。
- 快照和各目标待播放上下文跨插件重启保留，有效期为 30 分钟；无快照、过期、无效 schema 或同步保存失败时保留目标原上下文。源设备离线、unknown、超时或存储失败不清除有效记录，仍可使用未过期快照及其固定位置。
- 快照写入按账号串行，并以账号内单调 `revision` 拒绝旧写入；`updated_at` 仅用于时间诊断。删除账号时删除快照，新账号标识不继承；不迁移试做存储数据。
- 播放成功后立即写入基础快照；暂停、停止或切换请求开始时更新状态与位置。切换请求开始时仅采样源设备物理位置并写入当前快照；若尚无有效快照，本次切换不创建快照，目标设备保留原待播放上下文。
- 首次成功播放无法取得位置时仍写入快照，位置记为 `0` 并将 `position_available` 设为 `false`；已有快照采样失败时保留旧位置与旧快照时间，不创建新版本，也不清除目标有效待播放上下文。
- 设备组使用共享播放管理器，但不产生跨设备同步快照；只有独立设备的符合范围播放才更新账号级快照。

## 设备切换与待播放上下文

- 切换仅写待播放上下文，不覆盖目标活动上下文，也不向音箱播放、暂停或停止。目标设备正在播放时同样只写待播放上下文；设备组成员完全跳过同步。
- 切换路径不得触发 `resumeAfterReload` 自动起播；插件启动和热重载保留既有恢复行为。
- `toggle` 在目标正在播放时执行暂停；目标未播放且有有效待播放上下文时优先使用它。明确 `resume` 也优先使用有效待播放上下文；没有待播放上下文才使用目标原活动上下文。
- 继续操作等待同一目标的异步同步任务。加载与起播分离：准备歌单、歌曲、位置、倍速、模式和 paused/stopped 状态时不生成 URL、不启动切歌定时器；准备成功后才下发，确认起播成功才提交新活动上下文并清除待播放上下文。
- 后端在目标设备收到播放新歌单或新歌曲的请求时清除待播放上下文，并使该目标未完成的同步任务失效；清除发生在加载与起播之前。前端切换歌单选择本身只在本地改状态、不通知后端，因此不作为清除信号。
- 跨账号切换只更新当前选择，不把源账号快照写入目标账号。

## 继续、恢复与失败处理

- 快速连续切换按最新 revision 生效；旧任务不得覆盖新目标。同一目标内容未变化时去重且不刷新有效期，内容变化才更新。
- 快照超过 30 分钟后，若源设备仍在播放符合范围的内容且本次采样成功，切换请求可以创建新 revision；采样失败则保留旧记录，目标设备保持原上下文。
- 待播放上下文有效期从首次写入时开始计算；同一内容去重不刷新 `expires_at`，内容或 `source_revision` 变化才替换并重新计时。
- 加载、URL 生成或推流在下发前失败时保持目标不变；下发后失败、超时或结果未知统一视为结果不确定，保留原本地记录和待播放上下文，沿用现有核验逻辑并报告失败，不自动重播旧歌曲。
- 歌曲恢复按 ID、索引、首曲回退；歌单不存在或为空时返回错误并保留目标原上下文。只有命中原 ID 才恢复位置，回退到其他歌曲从 0 秒开始，保留倍速和播放模式。
- 电台纳入快照，`content_type` 为 `radio`、`playlist_id` 为 `null`、位置固定为 0，身份沿用 `song_id`；正式歌单歌曲使用 `content_type` 为 `playlist`、`playlist_id` 必填。未知时长沿用快照位置，seek 精度由播放服务决定；接近曲尾遵循现有安全位置规则。上述情况按降级行为验收，不套用精确位置误差要求。
- 设备选择本身成功后，即使后台同步失败接口仍返回成功；同步错误由日志和后续继续操作报告。
- 目标设备离线、unknown 或未启用管理时仍可保存 pending；用户继续时才按统一规则报告失败。

## 语音行为

- 普通语音和 AI 区分 pause、stop、resume；旧 AI 返回 `stop` 始终按停止处理，只有明确解析为 `pause` 才暂停。

## 数据契约

`schema_version`、`revision` 为整数，缺失或未知 schema 无效；`position_available` 为布尔值；`content_type` 只能是 `playlist` 或 `radio`。`playlist` 快照必须有 `playlist_id`；`radio` 快照必须有 `playlist_id` 为 `null`。`song_id` 是歌曲身份匹配依据，电台与正式歌单歌曲共用该字段，未命中时采用上文回退规则；标题和歌手仅用于诊断。不读取试做版本的存储键或数据。
- 同步数据分属两个专用存储键：播放快照用 `playback_snapshot_v1`，信封结构为 `{ schema_version: 1, snapshots }`，`snapshots` 按账号保存一条；待播放上下文用 `playback_pending_v1`，信封结构为 `{ schema_version: 1, pending }`，`pending` 按账号和目标设备保存一条。账号删除时同时删除两个键中该账号的数据，后续新账号 revision 从 `1` 开始。
- 下发结果使用 `succeeded`、`failed`、`unknown` 三值；`unknown` 对外报告为 `success: false`、`outcome: 'unknown'`，不回滚设备、不自动重播、不清除待播放上下文。
- 快照由 `PlaylistManager` 的状态机出口统一记录，因此网页、普通语音、AI、定时任务、睡眠定时器和内部自动停止都自动覆盖；设备物理按键或外部应用造成的状态变化不主动写快照。暂停被设备升级为停止时按实际结果写入 `stopped`。
- 设备选择接口始终返回 `success: true`，同步在后台执行；`toggle`、明确 `resume` 和实际播放接口返回 `outcome`。电台恢复按 `song_id` 取回同一播放服务的歌曲对象，取不到则保留目标原上下文并报告失败。
- 后端在目标设备收到播放新歌单或新歌曲的请求时立即清除 pending 并使旧同步任务失效，先于加载与起播；正式歌单自动切歌成功后立即更新账号级快照，自动切歌失败则保留上一条有效快照。
- 读取上述两个存储键时，未知信封 schema 忽略整个信封；单条快照或 pending 字段错误只忽略该条并记录诊断日志，不清空其他账号或设备数据。源设备位置采样超过 2 秒视为失败。

## 验收

纯逻辑测试使用独立内存存储和 mock 宿主 API，覆盖有效期、隔离、去重、revision、回退和状态；宿主集成测试使用真实宿主验证存储、歌单、设备状态和播放调用。集成验收须检查切换不发控制命令、不覆盖活动上下文，继续才发 URL，成功清除、失败保留，以及设备组跳过。夹具不得写入真实用户存储。需求整理阶段不添加业务测试；任务 01、02 进入实现阶段后，必须补充覆盖验收场景的纯逻辑及集成测试。

真机验收覆盖独立设备、设备组、目标播放中切换、快速切换、弱网/离线/unknown/超时、歌单或歌曲变化、重启和过期、特殊歌曲及旧 AI `stop`。

纯逻辑测试优先使用 Node 内置 `node:test` 和独立内存 fake，避免引入重量级测试框架。验证入口：

- `npm test` 运行 `src/**/*.test.ts` 的纯逻辑测试。Node 24 原生剥离 TypeScript 类型，测试文件用 `.ts` 直接执行，因此相对导入必须带 `.ts` 扩展名（`tsconfig` 已开启 `allowImportingTsExtensions`）。
- `npm run typecheck` 运行全量 `tsc --noEmit`。
- `node frontend/tests/run.mjs` 运行前端合同测试；该入口已修复为任意工作目录、任意平台换行都能通过。

命名约定：测试文件以 `.test.ts` 结尾，否则不会被 `npm test` 发现。
