# 音响切换续播

Status: ready-for-agent

## 背景

用户在 FNOS Docker 中运行插件，可能在多台独立音响之间切换。当前项目能读取设备状态、保存歌单进度并通过 WebSocket 推送，但缺少跨独立设备的最近播放续播协调。

## 目标

1. 切换到另一台设备时，界面显示最近有效播放的歌曲和曲内位置。
2. 重启或容器重建后，快照仍可用。

## 非目标

- 不做实时同步或后台镜像。
- 不承诺帧级或零延迟同步。
- 不替换设备组已有的共享 PlaylistManager。
- 不把外部脚本作为主实现。

## 方案约束

- 状态读取复用 resolvePlayerStatus 和设备缓存。
- 目标播放必须重新生成可访问 URL，并复用 PlaylistManager 的 seek/倍速处理。
- 切换音响只更新当前设备和进度视图，不向目标设备自动下发播放。
- 用户点击播放后，才依据最近快照重新生成 URL 并带 seek 位置起播。
- 最近播放快照默认有效期 30 分钟。
- unknown、网络超时和设备离线不得清除快照。

## 数据

快照至少包含 accountId、sourceDeviceId、playlistId、songId、songIndex、positionSec、durationSec、speed、state、updatedAt。最近播放快照按账号保存一份全局记录；原有每设备/每歌单进度继续保留，作为快照失效时的回退来源。快照默认有效期为 30 分钟。

## 切换规则

- 同一设备组继续由 GroupCoordinator 处理，不创建跨设备同步任务。
- 切换目标设备正在播放时，不强制打断。
- 切换后只展示最近快照；不自动发声、不自动暂停，也不自动重建 URL。
- 用户点击播放或继续播放后，依据最近快照重新生成 URL 并带 seek 位置起播。
- 快照过期后按歌单持久化进度恢复；当前歌曲已删除时先按歌单索引回退，索引也失效时从歌单头部开始。
- 目标设备离线或推送失败时返回可识别错误，不影响源设备和快照。
- Docker 重启后只恢复快照数据，不自动唤醒音响播放。
- 目标设备正在播放且未显式切换时，不强制打断。

## 验收标准

- 切换设备后，在网络正常且快照未过期时，目标设备恢复同一首歌，位置误差不超过 5 秒。
- FNOS Docker 重启后快照仍存在。
- 单台设备离线不会阻塞源设备。
- 一期提供“切换音响”和“播放最近进度”两个独立动作。

## 明确不做

- 不自动识别并切换源设备。
- 不支持一个源设备同时追踪多个目标设备。
- 不做后台追赶进度或跨设备实时状态镜像。
